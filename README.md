# 风见（Windcatcher）· 鼻腔气流工作台

> 参赛队「空穴来风」｜本地优先、免登录、不上传任何影像或结果
> 阶段一目标：把一份经授权的鼻腔 CT 变成可复核的气道模型与气流计算结果

## 研究预览版说明

当前版本定位为 **Windcatcher v0.1 Research Preview（研究预览版）**。它适合开发者、竞赛评审和经过培训的研究人员在本机复核“CT → 气道模型 → CFD → 流场可视化”的流程。项目仍在验证真实病例的收敛性、网格敏感性、几何拓扑和解剖范围，不能把预览结果当作临床诊断、手术计划、治疗建议或鼻塞产品定型依据。

使用真实病例前，请确认已经获得数据使用授权，并在本地完成去标识。公开发布或提交问题时只应使用合成 CT、截图或已脱敏的统计信息；不要上传 DICOM、STL、CFD 场文件、病例报告、API 密钥或包含患者信息的日志。仓库中的测试链路默认使用 `tests/phantom_ct` 合成数据。

### 预览版已知边界

- 真实病例可以执行基准稳态 CFD 并查看已有流场，但达到迭代上限不等于已经证明稳态收敛；正式指标仍受结果闸门约束。
- 浏览器中的流线和粒子是对已计算速度场的后处理，不是实时求解，也不是吸气/呼气周期模拟。
- 鼻塞方案重新求解、瞬态呼吸计算、AI 自动分割和精确自交检查仍属于后续工作或待复核能力。
- 完整候选默认保留鼻腔、鼻窦和旁支；鼻窦是否纳入 CFD 必须结合 CT、端面和连通性人工确认，软件不会静默替用户删除结构。

### 建模范围政策

- **完整候选范围是默认复核对象**：它用于尽量保留患者 CT 中的鼻腔、鼻窦和旁支，避免在影像阶段先把可能影响窦口交换、局部压力或壁面指标的结构删掉。
- **主鼻腔气流模型是对照范围**：只保留从鼻孔到鼻咽的主通道，适合做主通道阻力、速度分布和鼻塞/空鼻症气流对照。
- 鼻窦/旁支不会自动变成入口或出口。完整候选若出现断开的表面组件，必须先在三平面视图、3D Slicer、Blender 或 SimScale 中确认窦口是否真实连通；未确认前，工作台会阻断 CFD 算例生成，不会静默删除组件。
- 这两个范围都来自同一份 CT 和同一套人工复核记录，切换范围后必须重新生成 STL、几何质检和 CFD 算例。

### 在工作台选择鼻孔端与鼻咽端

1. 导入 CT、分割气道，在三平面视图清理体外空气并人工确认掩膜。
2. 在“STL 与几何”的端面工具中选择建模范围，先按已确认掩膜的原始体素分辨率重建三维气道，再由用户在模型上选择鼻孔侧、鼻咽侧并调整裁切面。CT 切片用于辅助核对，不要求先逐张定位端点。选择模型不降采样、不简化面数、不做几何平滑；软件不会替用户判断解剖位置。
3. 保存两个截面后再生成 STL。工作台保存切面位置、法向及当前掩膜版本；生成 STL 时才裁切所选范围。掩膜编辑或重新分割后必须重新确认端面。
4. 查看 STL 与几何质检。前后端至少有一个面积不小于 1 mm² 的开口才可进入 CFD 算例准备；这个数字只用于排除离散化毛刺，不代表临床上正确的入口或出口。完整候选仍须处理断开的鼻窦或旁支组件。

CFD 算例准备会基于通过质检的开口创建入口、出口边界面并设置求解条件。当前流程使用本地 OpenFOAM，不会向 SimScale 上传病例数据。

### 查看当前病例的真实气流

1. 打开侧栏“病例流场”，选择已有求解场的病例。浏览器读取该病例的结果，显示来源病例和时间步。
2. 首次没有结果时，点击“生成可视化”；该动作只读取已有场，不重新划网格或求解。可以查看进度、取消或失败后重试。
3. 选择速度或压力，调整模型透明度，查看三个内部截面；流线、入口/出口可以分别显示或隐藏。拖动模型旋转，滚轮缩放，“重置视角”恢复视角。
4. 用播放/暂停、播放倍率和每条流线的粒子数观察稳态轨迹。动画来自已计算速度场，**不是实时求解，也不是吸气/呼气周期模拟**。采样流线没有覆盖的位置不表示那里没有气流。
5. 查看下方验证项。“真实流场已生成”表示可查看计算输出；“尚未整体通过”表示仍不能用作已验证的基准 CFD。

压力色标以结果中记录的单位为准。现存真实病例的 p 是运动学压力 `m²/s²`；未记录空气密度时不换算为 Pa。

后处理以当前最终时间步和网格为来源。结果来源变化会标为过期；重新发布结果前保留上一份已完成产物，刷新页面可重新加载进度。

浏览器流场直接读取 OpenFOAM 网格及最终时间步的 `U`、`p`，不依赖附加的 `foamToVTK` 文件导出。若求解已经完成、仅 VTK 导出失败或超时，可在“病例流场”单独生成可视化，无需重新求解。新版附加导出只处理最终时间步的速度与压力，使用二进制格式；不完整的旧 VTK 文件不能作为结果使用。能展示真实场不代表收敛或网格复核已经通过，页面仍显示“待复核”。

自由切面建模先生成闭合原始壳，再按用户选定的鼻孔/鼻咽切面裁切。该修复只影响之后生成的模型；已有旧 STL 和 CFD 场不会自动重建。

工作台提供“最强 / 适度 / 自定义”CPU 资源模式。Docker 并行求解会先执行最多 60 秒的启动预检，读取容器可用线程数与 CPU 配额，并用相同 MPI 配置测试启动；超过后端资源上限时会在生成网格之前停止并显示原因。Windows 物理核心数不等于 Docker / WSL 的虚拟核心数，Docker 使用 `--use-hwthread-cpus` 分配实际虚拟 CPU 线程，不启用超额进程分配。

当前 Docker / OpenFOAM 11 后端会对 `snappyHexMesh` 网格生成与气流求解都使用选定的 MPI 进程数。先分解背景网格，并行贴合气道，再重建完整网格、运行 `checkMesh`，最后重新分区初始场并求解。其他后端保留原有网格流程，页面以实际运行记录显示并行或串行。标准 `simpleFoam` 不使用 GPU。

同一算例可以复用已经检查的网格：核对几何、网格字典、实际 Docker 镜像内容及所有网格文件的 SHA-256；输入变化、文件损坏、网格步骤失败或缺少可靠记录时重新生成。只调整求解核数、流量或迭代设置不会因此重建网格；每次复用仍重新执行 `checkMesh`、分区和求解，质量警告仍保留。历史网格没有复用记录，因此升级后第一次运行需要重建，此后符合条件的重试可以跳过建网格。

运行记录展示本次“并行生成 / 单进程生成 / 复用已生成网格”、进程数及复用原因。旧时间目录、分区、流场可视化与统计会移至 `cfd/run_history/<本次运行编号>/`，防止失败重试把旧场显示成新结果。归档占用本机磁盘，工作台不会自动删除。资源预检失败时保留原有结果。真实病例仍需重新运行及收敛、质量守恒、网格质量复核，短教程验证不能代替患者网格验证，也不代表固定加速倍数。

## 本机操作监控

风见服务启动时自动开启操作记录，无需另起程序。浏览器刷新后，环境页底部的“本机操作记录”可查看最近 50 条记录，并筛选失败与错误。

记录覆盖页面、按钮、控件数值、CT/3D 操作摘要、掩膜编辑、请求状态/耗时、阶段变化及 JavaScript 错误类型。连续滚轮、拖动和数值输入合并记录；不会逐帧录像，也不会记录文件夹路径、文本输入、API 密钥、请求内容、CT 图像或原始错误文本。参考样本 iframe 和外部桌面软件内的操作不在采集范围内。

日志仅写入 `.local-monitor/activity.sqlite3`，该目录已排除版本控制；保留 14 天，最多 50,000 条。时间在数据库中为 UTC，页面按浏览器本地时区显示。前端离线队列有上限和有限次重试，送达失败或丢弃数量会在面板提示；关闭服务期间不采集后台请求。

可供本机开发者查询的接口：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/monitor/status
Invoke-RestMethod 'http://127.0.0.1:8765/api/monitor/events?latest=true&limit=50'
Invoke-RestMethod 'http://127.0.0.1:8765/api/monitor/events?errors_only=true&after=0&limit=100'
```

增量查询使用 `next_after` 作为下一次 `after`；可加 `case_id`、`session_id`、`kind` 筛选。`latest=true` 仅用于最近记录视图。请求号将浏览器请求和服务端处理关联起来；浏览器记录另有会话内序号与操作时间，避免批次发送延迟改变操作顺序。需要时可在后续会话查询这些记录，当前助手不会在会话结束后持续阅读日志。
