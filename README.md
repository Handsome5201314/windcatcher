## 研究预览版说明

当前版本定位为 **Windcatcher v0.1 Research Preview（研究预览版）**。它适合开发者、竞赛评审和经过培训的研究人员在本机复核“CT → 气道模型 → CFD → 流场可视化”的流程。项目仍在验证真实病例的收敛性、网格敏感性、几何拓扑和解剖范围，不能把预览结果当作临床诊断、手术计划、治疗建议或鼻塞产品定型依据。

使用真实病例前，请确认已经获得数据使用授权，并在本地完成去标识。公开发布或提交问题时只应使用合成 CT、截图或已脱敏的统计信息；不要上传 DICOM、STL、CFD 场文件、病例报告、API 密钥或包含患者信息的日志。仓库中的测试链路默认使用 `tests/phantom_ct` 合成数据。

### 预览版已知边界

- 真实病例可以执行基准稳态 CFD 并查看已有流场，但达到迭代上限不等于已经证明稳态收敛；正式指标仍受结果闸门约束。
- 浏览器中的流线和粒子是对已计算速度场的后处理，不是实时求解，也不是吸气/呼气周期模拟。
- 鼻塞研究方案已支持独立后台重算和同工况对比；AI 自动分割、个性化鼻塞生成、打印交付和瞬态呼吸计算仍属于后续工作或待复核能力。
- 新病例默认选择主鼻腔气流模型；手动选择完整候选时会保留鼻腔、鼻窦和旁支，浏览器会记住每例的手动选择。鼻窦是否纳入 CFD 必须结合 CT、端面和连通性人工确认。

### 建模范围政策

- **完整候选范围是默认复核对象**：它用于尽量保留患者 CT 中的鼻腔、鼻窦和旁支，避免在影像阶段先把可能影响窦口交换、局部压力或壁面指标的结构删掉。
- **主鼻腔气流模型是对照范围**：只保留从鼻孔到鼻咽的主通道，适合做主通道阻力、速度分布和鼻塞/空鼻症气流对照。
- 鼻窦/旁支不会自动变成入口或出口。完整候选若出现断开的表面组件，必须先在三平面视图、3D Slicer、Blender 或 SimScale 中确认窦口是否真实连通；未确认前，工作台会阻断 CFD 算例生成，不会静默删除组件。
- 这两个范围都来自同一份 CT 和同一套人工复核记录，切换范围后必须重新生成 STL、几何质检和 CFD 算例。

### 在工作台选择鼻孔端与鼻咽端

1. 导入 CT、分割气道，在三平面视图清理体外空气并人工确认掩膜。
2. 在“端面裁切 → 候选与纠错”点击“本机生成候选”，可从已确认的主气道掩膜获得待复核方案；左/右鼻孔若分别通过技术预检，会作为两条记录出现。逐条加载到草稿并对照 CT 核对。也可以手动先选鼻孔端，点击模型放置切面，再用前后移动（mm）、上下/左右倾斜滑块微调；点选完成后普通点击不会改变切面。亮色轮廓显示真实模型与切面的交线，右侧显示同一位置和角度的 CT 重采样截面；绿色轮廓为当前范围掩膜。核对后“保存鼻孔端并继续”，再选择鼻咽端。支持撤销；三点定面与三轴手柄收在“高级调整”，也可展开 CT 层号进行正交选面。选择模型不降采样、不简化面数、不做几何平滑；软件不会替用户判断解剖位置。
3. 分别选择并保存鼻孔侧、鼻咽侧两个截面后再生成 STL。单侧保存会保留另一端的已保存方案；两端通过联合预检后，工作台才允许生成模型。工作台保存切面位置、法向及当前掩膜版本；生成 STL 时才裁切所选范围。掩膜编辑或重新分割后必须重新确认端面。

端面 CT 预览使用 `POST /api/cases/{case_id}/segment/endplanes/section`，接收当前 `scope`、`mask_version`、LPS 毫米坐标 `plane` 和显示范围 `span_mm`，返回不缓存的 PNG。该接口只读取已人工确认的当前版本，不保存端面、不使旧 STL/CFD 失效；每次明确保存端面仍会使下游产物失效。三点定面要求三个分散、非共线的点，无法确定时会提示重选。
4. 查看 STL 与几何质检。前后端至少有一个面积不小于 1 mm² 的开口才可进入 CFD 算例准备；这个数字只用于排除离散化毛刺，不代表临床上正确的入口或出口。完整候选仍须处理断开的鼻窦或旁支组件。

CFD 算例准备会基于通过质检的开口创建入口、出口边界面并设置求解条件。当前流程使用本地 OpenFOAM，不会向 SimScale 上传病例数据。

### 鼻塞方案研究闭环（第一阶段）

鼻塞方案现在具备一条可追溯的研究闭环：**上传 STL → 几何预检 → 气道/鼻塞 3D 叠加预览 → 人工摆位 → 版本化审核 → 独立 OpenFOAM 算例 → 后台求解 → 与同工况基准前后对比 → 下载资产和结果**。这条链路已通过合成几何和隔离 OpenFOAM runner 冒烟验证；真实鼻腔几何仍必须完成网格敏感性、残差收敛、质量守恒以及工程/临床复核后，才可作为研究结论。鼻塞实体作为独立 `plug` wall 障碍物加入该版本的 `snappyHexMesh`，不会覆盖基准病例算例。方案目录独立于 `surface/`、`cfd/` 和 `report/`，病例重新分割时不会清理已经上传的研究资产。

接口契约如下：

```text
POST /api/cases/{case_id}/scenarios                 multipart: model=<STL>, unit=mm|cm|m|inch
GET  /api/cases/{case_id}/scenarios
GET  /api/cases/{case_id}/scenarios/{scenario_id}
PUT  /api/cases/{case_id}/scenarios/{scenario_id}/placement
POST /api/cases/{case_id}/scenarios/{scenario_id}/review
POST /api/cases/{case_id}/scenarios/{scenario_id}/cfd-prep
POST /api/cases/{case_id}/scenarios/{scenario_id}/cfd-run       （立即返回后台任务）
GET  /api/cases/{case_id}/scenarios/{scenario_id}/cfd-status
GET  /api/cases/{case_id}/scenarios/{scenario_id}/comparison
GET  /api/cases/{case_id}/scenarios/{scenario_id}/download?artifact=bundle
```

摆位接口中的 `translation_mm`、`rotation_deg`、`scale` 都是三轴数组，并且必须带当前 `expected_version`；审核接口同样必须带版本号，防止旧页面覆盖新摆位。每次摆位都会生成新的不可覆盖版本，版本目录保存当时的方案快照、任务记录和审计 JSONL。病例根目录的 `research.sqlite3` 会保存版本快照、业务事件，以及已登记的 STL/任务/CFD JSON 产物相对路径、字节数与 SHA-256；网格和场等大文件仍按版本目录保存，只在数据库中登记索引。叠加预览与后端使用同一套毫米坐标、`Rz * Ry * Rx` 旋转顺序；服务端还会检查顶点/面心是否在气道壳内、鼻塞表面是否与气道壳相交，以及 `locationInMesh` 是否落入鼻塞实体。方案绑定分割版本、气道 STL/清单和端面摘要的 SHA-256 指纹；病例气道重新生成后会显示 `base_status=stale`，不能沿用旧摆位审核或比较。`cfd_ready=true` 只在该版本的独立算例准备完成后写入；求解任务状态为 `queued/running/solved/failed/blocked`，公网请求不会同步等待求解器。下载默认每次按所选版本重建相对路径 zip，包含原始 STL、毫米规范化 STL、摆位 STL、摆位/审核记录、版本清单、CFD 输入和对比结果（若已生成）。活动监控 SQLite 仍是短期运行日志；研究账本与病例产物一起长期保留，但当前仍不是长期多租户数据库。该闭环只用于研究预览，数值通过后仍需网格敏感性、CFD 工程师和临床团队复核，不输出医疗器械建议。

### 查看当前病例的真实气流

1. 打开侧栏“病例流场”，选择已有求解场的病例。浏览器读取该病例的结果，显示来源病例和时间步。
2. 首次没有结果时，点击“生成可视化”；该动作只读取已有场，不重新划网格或求解。可以查看进度、取消或失败后重试。
3. 选择速度或压力，调整模型透明度，查看三个内部截面；在“截面气流分布”中直接拖动模型上的橙色分析截面，松开鼠标后会复用已有最终速度场重新切片并计算整截面面积、正向/反向/净流量及面积加权速度（无需重新求解 CFD）。滑杆和按钮可作为备用定位方式；左右、上中下人工区域仅作为旧结果兼容读取。
4. 用播放/暂停、播放倍率和每条流线的粒子数观察稳态轨迹。动画来自已计算速度场，**不是实时求解，也不是吸气/呼气周期模拟**。采样流线没有覆盖的位置不表示那里没有气流。
5. 查看下方验证项。“真实流场已生成”表示可查看计算输出；“尚未整体通过”表示仍不能用作已验证的基准 CFD。

压力色标以结果中记录的单位为准。现存真实病例的 p 是运动学压力 `m²/s²`；未记录空气密度时不换算为 Pa。

后处理以当前最终时间步和网格为来源。结果来源变化会标为过期；重新发布结果前保留上一份已完成产物，刷新页面可重新加载进度。

浏览器流场直接读取 OpenFOAM 网格及最终时间步的 `U`、`p`，不依赖附加的 `foamToVTK` 文件导出。若求解已经完成、仅 VTK 导出失败或超时，可在“病例流场”单独生成可视化，无需重新求解。新版附加导出只处理最终时间步的速度与压力，使用二进制格式；不完整的旧 VTK 文件不能作为结果使用。能展示真实场不代表收敛或网格复核已经通过，页面仍显示“待复核”。

自由切面建模先生成闭合原始壳，再按用户选定的鼻孔/鼻咽切面裁切。该修复只影响之后生成的模型；已有旧 STL 和 CFD 场不会自动重建。

工作台提供“最强 / 适度 / 自定义”CPU 资源模式。Docker 并行求解会先执行最多 60 秒的启动预检，读取容器可用线程数与 CPU 配额，并用相同 MPI 配置测试启动；超过后端资源上限时会在生成网格之前停止并显示原因。Windows 物理核心数不等于 Docker / WSL 的虚拟核心数，Docker 使用 `--use-hwthread-cpus` 分配实际虚拟 CPU 线程，不启用超额进程分配。

当前 Docker / OpenFOAM 11 后端会对 `snappyHexMesh` 网格生成与气流求解都使用选定的 MPI 进程数。先分解背景网格，并行贴合气道，再重建完整网格、运行 `checkMesh`，最后重新分区初始场并求解。其他后端保留原有网格流程，页面以实际运行记录显示并行或串行。标准 `simpleFoam` 不使用 GPU。

同一算例可以复用已经检查的网格：核对几何、网格字典、实际 Docker 镜像内容及所有网格文件的 SHA-256；输入变化、文件损坏、网格步骤失败或缺少可靠记录时重新生成。只调整求解核数、流量或迭代设置不会因此重建网格；每次复用仍重新执行 `checkMesh`、分区和求解，质量警告仍保留。历史网格没有复用记录，因此升级后第一次运行需要重建，此后符合条件的重试可以跳过建网格。

运行记录展示本次“并行生成 / 单进程生成 / 复用已生成网格”、进程数及复用原因。旧时间目录、分区、流场可视化与统计会移至 `cfd/run_history/<本次运行编号>/`，防止失败重试把旧场显示成新结果。归档占用本机磁盘，工作台不会自动删除。资源预检失败时保留原有结果。真实病例仍需重新运行及收敛、质量守恒、网格质量复核，短教程验证不能代替患者网格验证，也不代表固定加速倍数。

## 启动方式

当前对外工作的目标形态是 **Windows 本机工作台 + SSH 反向隧道公网入口**，由 `scripts/Start-PublicAccess.ps1` 守护。个人账号模式的开发与发布验收以这条链路为准，魔搭创空间是独立部署，不参与本轮上线门槛。

## 本机操作监控

风见工作台会自动记录白名单内的操作事件。共享公网工作台登录后，可从左侧“操作记录”查看最近 50 条和错误筛选；个人账号模式下，浏览器事件由服务端绑定账号，完整操作日志仅管理员可读，个人可在“环境”页按需分析自己的使用习惯线索。访客与患者分享页面不采集这些事件；网关要求已登录且同源请求。

记录覆盖页面、按钮、控件数值、CT/3D 操作摘要、掩膜编辑、请求状态/耗时、处理阶段和 JavaScript 错误类型。连续滚轮、拖动和数值输入会合并；不录屏，不保存文本输入、文件路径、API 密钥、请求内容、CT 影像或原始错误文本。参考样本 iframe 和外部桌面软件内的操作不在采集范围内。

日志默认写入服务端 `.local-monitor/activity.sqlite3`，也可通过本机 `.env` 的 `WINDCATCHER_MONITOR_DIR` 指定持久目录。旧格式数据库会原位升级并保留历史记录。共享/本机模式不自动过期；个人账号模式按服务端 UTC 时间保留 180 天，在写入、读取、备份前及服务启动后每小时清理，清理后截断 SQLite WAL。**旧备份里的过期事件不会因此消失**；正式启用前须按 [身份与备份说明](docs/identity-backup.md#操作元数据) 逐目录审计。数据库另含事件格式和应用版本；界面按浏览器时区显示。前端队列有上限且最多重试数次，送达失败或丢弃数量会在页面提示。该数据库保存在当前服务主机，不会自动复制到其他机器或进入版本库；主机磁盘损坏仍可能丢失数据。可在服务运行时用 SQLite 在线备份命令生成一致快照，目标文件必须尚不存在：

```powershell
.\.venv\Scripts\python.exe scripts\backup_activity_monitor.py E:\windcatcher-backups\activity.sqlite3
```

操作记录是待整理的过程元数据，不会自动训练模型；患者反馈、合伙人反馈和经人工审核的自动化评测数据应独立存储与筛选。

公网记录接口仅供带有效登录会话的同源工作台使用。增量查询使用 `next_after` 作为下一次 `after`；可加 `case_id`、`session_id`、`kind` 筛选。`latest=true` 仅用于最近记录视图。请求号将浏览器请求和服务端处理关联起来；浏览器记录另有会话内序号与操作时间，避免批次发送延迟改变操作顺序。需要时可在后续会话查询这些记录，当前助手不会在会话结束后持续阅读日志。
